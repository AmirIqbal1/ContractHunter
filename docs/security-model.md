# Security model

ContractHunter is a single-user local tool for authorised analysis. It has no application authentication; do not expose the web port to an untrusted network. Repository content is hostile input. Dependency preparation accepts only approved pinned Git submodules and lockfile-backed npm dependencies with lifecycle scripts disabled. AI receives bounded context and can propose structured data, but has no command, filesystem, RPC, wallet, or verification execution authority.

## v0.1.9 verification boundary

The web service validates persisted scan and hypothesis state, builds a deterministic workspace from an allowlisted Solidity source closure, writes its own `foundry.toml` with `ffi = false`, checks file hashes, and sends only job identifiers and bounded limits over a Unix-domain socket. It interprets execution facts and owns all dynamic evidence and lifecycle transitions. A successful process alone cannot verify a hypothesis; only completed, confirmed, valid supporting dynamic evidence can do so.

The separate `verification-worker` has `network_mode: none`, no ports, no Compose network, no Docker socket, and no application API credentials. It runs as UID 10002 with the shared ContractHunter GID 10001, a read-only root filesystem, bounded tmpfs, `pids_limit: 64`, no capabilities, `no-new-privileges`, and Docker's default seccomp and enforcing AppArmor profile. It receives only the verification workspace volume, a small socket volume, and the read-only `tool-home` subpath of the existing data volume. The main database and repository store are not mounted.

At startup and before every job the worker checks its UID/GID, zero effective and bounding capabilities, `NoNewPrivs=1`, seccomp mode 2, enforcing AppArmor, cgroup PID limit, loopback-only interfaces, lack of usable default routes, forbidden environment keys, and absence of database, repository, and Docker socket paths. A failed check prevents Forge execution. The Unix socket is group-owned and mode 0660. The RPC is length-prefixed JSON with a 4096-byte request cap, strict schema, one `verify` command, UUID workspace identifier, and no source or arbitrary command arguments.

The worker revalidates the workspace realpath, strict manifest identity, source and harness hashes, exact generated configuration, expected layout, and trusted compiler. The compiler must be the exact regular, non-symlink solc-select artifact below the read-only cache, must execute `--version` successfully, and must report the requested stable version. Forge runs with fixed `test --color never` arguments and an optional sanitized `--match-test` identifier. The child environment is constructed from scratch with offline compiler selection, FFI disabled, no proxy, secret, wallet, or RPC variables. `prlimit` bounds CPU time, virtual memory, process count, file descriptors, and file size; the controller bounds wall time and captured output.

Nested Bubblewrap verification was retired because Docker's masked/read-only `/proc` mounts blocked Bubblewrap's new proc mount even after its namespace creation succeeded. No custom mount/namespace seccomp rule, broad AppArmor mount permission, unconfined Docker setting, privileged mode, host network, Docker socket, or dynamic container spawning is used. The web retains ordinary networking for scanning and optional AI, and cannot run verification Forge as a fallback.
